# Portable scientific experiences

PP-112 introduces a separate `paperplay-scientific-experience` format. Existing widget snapshots, HTML study packs, data-study v1/v2 files and artifact-experiment files keep their existing parsers and limits. An experience groups typed figures and their reproducibility metadata; it is not a workspace dump.

## Inclusion and reopening

A manifest identifies its exact normalized source and records entry content hashes, parameters, seeds, dependency/runtime identities, asset references, attribution and included validation history. Full normalized source and scientific assets require explicit inclusion. Figure anchors can contain short quoted excerpts even when full source inclusion is off. PDF bytes, personal notes, credentials, provider jobs and bearer capabilities are not copied from browser storage.

The ordinary reader exports mounted legacy/widget figures and their visible recorded values. A composed study exports its current plan, controls and semantic selections. A generated figure exports its current input and seed through the existing artifact bundle boundary. Each view offers inclusion controls before download. Scientific inputs are themselves data; review them before sharing even when attachment inclusion is off.

Import checks bounded structure, exact hashes, source identities and each existing format's validation rules. A missing source, omitted asset or unavailable dependency remains an explicit gap. The original imported file remains downloadable. Opening an experience must not silently replace the reader's source or call Muse.

Recorded values are historical, unverified captures. Compatible declarative views can be opened locally; generated interaction requires explicit admission through the existing approved compiler and isolated runtime. Imported cache metadata, rendered frames and scientific-validation history cannot recreate process-private compilation or live validation receipts. A copied report labeled passed remains reported history until independent checks run again for its exact current inputs.

## Static HTML

HTML study packs remain script-free captures. They can contain sanitized images, visible values, exact typed settings, citations and explicitly selected source/notes/PDF attachments. They do not execute generated code or acquire authority from an embedded manifest. Reopening a compatible typed experience happens in Paperplay through its normal admission boundaries.

## Compatibility and limits

The new container is bounded at 20 MiB. Existing per-entry caps remain in force rather than expanding a smaller data-study format into an unrestricted transport. Unsupported versions, corrupt hashes and mismatched dependencies return recoverable results. No format import performs an external fetch or paid creation.

Verification: TypeScript, the automated suite and production build pass. Eight focused codec tests cover mixed entries, zero-worker/zero-fetch inspection, source/asset inclusion, legitimate scientific token columns, raw input order, exact generated bindings, declaration-only validation history, nested attachment rejection, navigation rebinding and original-file recovery. The workspace checkpoint runs 723 tests including the prepared PP-113 evaluator infrastructure.

Native evidence is recorded in `data/experience-browser-ui.json` and `data/experience-browser-reader.json`. Authored fixtures distinguish structural/interaction checks from scientific evidence. Review and imported captured text create no worker; explicit approved interactions do. An authored decay-rate edit reopens with its changed value. Actual browser engine requests retain seeds 73 and 74, and switching entries clears the previous trace. At 320 px, the reader export dialog is contained and its visible buttons are 44 px with 16 px text; the new export panel also remains contained with enlarged text.

The reader exports figures with typed session/widget definitions. It reports captures without such a definition as omitted from the interactive file; their static visible capture remains available in the HTML study pack. Generated imported frames and exported frame text are explicitly historical. Browser corruption recovery checks outer-integrity rejection; separate automated tests cover a self-consistent container with an unsupported runtime/dependency.

A native asset-selection export uncovered a navigation revision bound to embedded asset bodies. Export now validates the original plan first, detaches selected bodies into the explicit attachment section, then recomputes the portable navigation revision while preserving the exact selection. Stale or out-of-bounds original selections remain rejected. No general selection validator was weakened.
