# Host-owned generated figures (PP-096)

Generated figures now run through the approved browser bridge after fresh local compilation. The host retains attribution, source navigation, stop controls, error messages and the unverified-evidence label. Generated JavaScript is interpreted only inside capped QuickJS/WASM in a dedicated Worker; the renderer receives validated JSON. [Isolation measurements](artifact-isolation.md) and [compiler admission](artifact-compiler.md) remain distinct from scientific validation. Muse generation/test/repair orchestration is the next PP-097 milestone; this delivery makes no model calls.

## Admission and execution

`buildFigureArtifact` validates the exact source document/version, quotation anchors, manifest, SDK/source digests and declared checked assets. `compileFigureInWorker` admits the generated script through the isolated compiler. Its validated result is frozen and registered in a private in-memory `WeakSet`. `createCompiledFigureAdapter` requires that actual local result and its matching manifest/source hashes. Imported JSON or a copied compiled envelope cannot create the receipt; it must be compiled again. Admission does not promote scientific evidence.

The existing build/run interface handles both declarative and generated artifacts. Generated execution still returns `disabled` when the caller supplies no approved adapter. The product preview supplies only the vetted `quickjs-wasm-worker@1.0.0` adapter after compilation. Each interaction gets a fresh Worker and interpreter, with prior state delivered as a JSON copy. Only the validated successful result becomes the next frozen frame/state. Guest global mutations do not persist between interactions.

The private Worker channel carries a UUID instance, sequence 1, the exact admitted manifest/envelope, copied input/state and a typed initialize/control/entity event. The Worker accepts one request. It rechecks manifest, source, SDK and compiled-envelope hashes and input/output interfaces. The owner checks the concrete Worker event target, its expected empty dedicated-Worker message origin, instance UUID, sequence and response schema. An empty message origin alone is not treated as authentication. One response is accepted; unknown fields, malformed output and inconsistent identities fail closed.

Buttons and sliders can emit only declared control IDs; disabled controls, missing entities, button values and out-of-domain slider values are rejected. The adapter allows at most 20 attempted interactions per second and two active runtime Workers in the current application instance. The second concurrency check occurs after asynchronous hashing/bootstrap, before creation. This is not a browser-wide limit across tabs.

## Checked infrastructure transport

The trusted project build emits content-addressed compiler/runtime files, fixed compatibility aliases and `artifact-workers.json`. Only fixed trusted entries are bundled, using the pinned parser/interpreter checks; generated source is never an esbuild entry. SDK source is read from the trusted repository module rather than duplicated. Metadata is published atomically after scripts exist, and older hash files are retained.

The production bootstrap fetches the small metadata file with `no-store`, validates the installed SDK digest and exact relative worker kind/hash URL, then fetches that same-origin script with `force-cache`. Redirects are rejected and no referrer is sent. Actual bytes must match both metadata and the hash embedded in the URL. The enforced response CSP must contain only `'self' 'wasm-unsafe-eval'` for scripts and `'none'` for connections and nested workers; permissive, missing or ambiguous policies are refused. JavaScript `unsafe-eval` is not enabled.

Metadata is limited to 8 KiB and scripts to 3 MiB, including streaming checks despite missing/forged Content-Length. Streams also cap at 4,096 chunks. Each caller owns its abort controller and eight-second bootstrap timeout; cancellation does not poison another caller's work. Only completed verified URLs are cached, keyed by origin, worker kind and SDK digest. Warm calls reuse that URL without repeating bootstrap fetches. The worker itself loads its immutable hash URL through the browser cache: the measured warm worker resource entries transferred zero bytes. There is no blob URL or native evaluation of downloaded source.

Hash-named files carry immutable year-long caching and the strict Worker CSP in Next's response headers. Fixed aliases and metadata remain `no-store`. The compiler's two-second and runtime's 1.5-second owner watchdogs start **after** verified infrastructure bootstrap, so ordinary first-load network time is handled separately from execution time. Cancellation remains available during both phases.

## Data, messages and resource ceilings

The reader retains a session-only approval pool per source/version: at most 16 checked assets and 8 MiB. Checksummed data from another source version, unchecked objects and silent same-ID replacement are rejected. A missing generated-figure binding exposes an exact ID/kind/hash importer. Confirmed assets are passed into the actual preview build; merely declaring a checksum does not approve data.

The guest receives the manifest's explicit `initialInput` fields plus only its declared checked asset bindings under the reserved `assets` object. The initial-input schema cannot inject that reserved field. Unrelated approved assets, the reader/workspace object, notes, credentials and inference authority are not added. Assets may themselves contain authorized source-derived content and attribution; this is not a claim that scientific data are public or anonymous.

The request ceiling is 768 KiB; response envelopes are bounded to 132 KiB, while each frame still obeys its own maximum 128 KiB output and 64 KiB state budgets. Structural checks reject non-JSON values, nonfinite numbers, more than 8,192 visited values, depth above 20 and oversized keys. Declared input/state fields and array length bounds are checked before use. The manifest caps source at 64 KiB, input at 256 KiB, marks at 512 and controls at 16; smaller declared limits remain binding.

The interpreter uses a maximum 64 MiB WASM memory, with the declared guest allocator capped at 32 MiB, stack at 512 KiB and guest-work interrupt budget at one second. Source execution and guest JSON hooks/getters stay inside that guest budget. The independent owner watchdog can terminate the Worker. These bounds do not cap total browser-process memory, guarantee every native parsing path polls an interrupt at a fixed interval, or certify the absence of future interpreter/browser vulnerabilities.

No host callbacks, DOM, storage, network, module loader, timers or inference functions are exposed to guest code. Date, Promise and Proxy intrinsics are omitted. SDK output supports circles, lines, rectangles, text, buttons, sliders and finite numerical/text tables. It provides no arbitrary HTML/CSS, URLs, native binaries, packages or guest WebGL/WebGPU. The trusted renderer never interprets returned text as code or markup. Marks must fit the declared drawing area rather than silently disappearing beyond it; source IDs, capability requests, control domains, unique IDs and table shape are validated.

## Reader behavior and recovery

The owned dynamic-sequence example opens with one gallery action. Imported artifacts require an explicit preview action. Compilation and execution remain local. Scientific evidence stays visibly unverified regardless of the generated title, a successful build or a correct-looking animation.

The renderer retains readable drawing size with bounded scrolling and an optional fitted overview. The sample declares a compact canvas for small sequences instead of leaving a large empty region. Text and values have separate readable tables. The mark disclosure includes complete text and geometric coordinates, so clipped SVG text is still accessible; drawing coordinates do not imply physical measurement units.

Slider movement uses a local draft, then commits on pointer release, supported key release or blur. A submitted value is deduplicated, and completion/failure restores the actual returned value. A synchronous current-job reference prevents overlapping state updates. Stop clears that reference before aborting; stale completions cannot replace the frame or clear a newer job's busy state. Source/input/data changes cancel stale code checks. Errors and resource exhaustion preserve the last valid figure and original source.

Semantic entity selections reuse the existing immutable selection store, with keyboard selection and undo/clear. Entity-set changes invalidate removed targets and their stale history. Selected-source actions open the relevant attribution disclosure or close the preview and focus the original paper passage. Host source/close controls remain outside generated output. The preview does not rewrite the paper or notes; saved/replayable artifact lifecycle remains a separate later gate.

## Evidence and limitations

`npm run check` passes TypeScript, **316 tests** and the production build. Tests cover local admission identities, exact hashes and declared-data filtering; immutable frames; instance/schema/payload checks; concurrency/cancellation; JSON/control/selection limits; stale-target pruning; infrastructure URL/hash/SDK/CSP checks; malformed and fragmented streams; repeat builds; warm bootstrap caching and independent caller aborts.

The native Chrome154/Linux production-bridge probes are recorded in [artifact-runtime-browser.json](../data/artifact-runtime-browser.json). The sequence grows from one to two items; cancellation returns a cancelled outcome. In parallel, the hostile job fails while the healthy job returns a valid frame. An authority probe succeeds only after confirming the tested host globals are absent; malformed output fails, and zero runtime Workers remain. Warm worker loads record zero transferred bytes. The [repeated isolation report](../data/artifact-runtime-isolation-browser.json) retains the 33 hostile/authority probes against the updated runtime, with 62 host heartbeat ticks and retained host storage. These are local engineering observations, not scientific or sandbox certification.

Actual Next-reader checks exercised the 320 px layout, 200% text/spacing reflow without page/dialog overflow, slider draft followed by blur commit, exact checked-data binding, source focus and the last valid frame surviving a hostile update. A host-only storage fixture remained intact; this was not a participant study or expert review. No paid model requests were made. Unsupported infrastructure/platforms and failed checks retain source-linked fallbacks. Broader browser support, deterministic scientific replay, generated tests/repair and domain evidence remain explicit further work.
