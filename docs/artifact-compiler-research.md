# PP-095 compile-only artifact preparation

Primary sources and installed declarations checked 28 October 2026. Recommend a **single-script compiler admission path**: bounded source → trusted Acorn parser/AST policy inside bounded QuickJS → QuickJS global compile-only check → deterministic source envelope. This is research, not a completed compiler or an isolation claim. No package was installed, artifact source executed or application code changed.

## QuickJS 0.32.0 behavior

Installed `node_modules/quickjs-emscripten-core/package.json` reports **0.32.0**. Its `dist/index.d.ts` defines `ContextEvalOptions.compileOnly` as compilation without running, returning a function-bytecode/module handle. Explicit global mode uses script/global semantics; module mode permits import/export and top-level await. [Release-tag options and flag conversion](https://raw.githubusercontent.com/justjake/quickjs-emscripten/v0.32.0/packages/quickjs-emscripten-core/src/types.ts).

Pass all relevant options explicitly: `type: "global"`, `strict: true`, `compileOnly: true`, with a fixed non-private diagnostic filename such as `artifact.js`. Omitting options enables an import/export-based module-detection heuristic. The release-tag context implementation forwards the flags into `QTS_Eval`. [Release-tag context evaluation](https://raw.githubusercontent.com/justjake/quickjs-emscripten/v0.32.0/packages/quickjs-emscripten-core/src/context.ts).

The C wrapper's global path calls `JS_Eval` with those flags and returns its handle; the compiler must dispose that handle and never call it, execute pending jobs or invoke `JS_EvalFunction`. **Avoid module compile-only for this first path**: the 0.32.0 wrapper also contains module namespace/promise postprocessing after the compile-only branch, with a module pointer assigned in the non-compile-only branch. This is a source-inspection concern, not a reproduced crash report. Explicit global mode avoids that code path. [Release-tag `QTS_Eval` implementation](https://raw.githubusercontent.com/justjake/quickjs-emscripten/v0.32.0/c/interface.c).

Set runtime allocation/stack limits before compilation and register the interrupt/deadline callback. Upstream documents interrupts as regularly called during execution; do not infer a hard parsing deadline from that wording. Keep source byte limits and a separate owner-thread watchdog covering parser, WASM load, compilation, diagnostics and cleanup. The owner can terminate a stuck Worker. QuickJS limits do not cap an Acorn parser running in the Worker's native JS environment, WASM baseline, copied input/output or total browser-process memory; the recommended placement below moves parser/AST work inside the interpreter. [QuickJS memory and interrupt APIs](https://bellard.org/quickjs/quickjs.html#Memory-handling), [Worker termination](https://html.spec.whatwg.org/multipage/workers.html#dom-worker-terminate).

## Acorn candidate

The npm registry currently reports **Acorn 8.19.0**, MIT, no runtime dependencies. Published exports provide ESM `dist/acorn.mjs` and CommonJS `dist/acorn.js`; types are supplied. It is a JavaScript parser rather than a build system, so it can be bundled into the reviewed browser compiler Worker without providing package installation or build commands to artifacts. Pin the exact version if adopted. [Published version metadata](https://registry.npmjs.org/acorn/8.19.0), [official manifest](https://raw.githubusercontent.com/acornjs/acorn/8.19.0/acorn/package.json), [MIT license](https://raw.githubusercontent.com/acornjs/acorn/8.19.0/acorn/LICENSE).

Acorn's `parse` returns an ESTree AST and syntax-error locations. Set a fixed supported `ecmaVersion`, `sourceType: "script"` and strict mode; avoid `"latest"`, loose parsing and plugins in the deterministic policy. Ensure the selected syntax level also compiles under the pinned QuickJS variant. Script mode rejects static module declarations; dynamic `import()` still requires an AST check. [Versioned official parser documentation](https://raw.githubusercontent.com/acornjs/acorn/8.19.0/acorn/README.md), [ESTree dynamic import node](https://github.com/estree/estree/blob/master/es2020.md#importexpression).

### Preferred parser placement: inside the bounded guest

The **published 8.19.0 tarball** was inspected without installing it. `package/dist/acorn.js` is a self-contained UMD file, **246,643 bytes**, SHA-256 `b95392d79457d0357555c5ed3e56302d074b92dff119bcf3b44179500b10e9df`. Its wrapper selects `globalThis.acorn` when CommonJS/AMD globals are absent. This supports loading the fixed, reviewed parser text into a normal QuickJS context rather than granting an artifact a module loader. [Published archive](https://registry.npmjs.org/acorn/-/acorn-8.19.0.tgz), [versioned distribution source](https://github.com/acornjs/acorn/tree/8.19.0/acorn).

Evaluating this pinned parser and a fixed policy walker is **trusted compiler setup**, distinct from executing artifact source. Supply model text with `context.newString`/property or argument handles; never interpolate it into generated wrapper JavaScript. Call `acorn.parse` on that string with the fixed script grammar, then traverse/check the AST inside QuickJS. Return only a tiny status/error-code/position result. Do not `dump` the AST or copy it into native host memory. This keeps parser objects, regular-expression validation and traversal within the guest engine's resource accounting.

Use a fresh parser context/runtime; dispose it before the subsequent compile-only runtime where practical. Loading roughly 247 KiB of trusted parser is a separate fixed setup budget, not permission to increase model source limits. Include parser bytes/hash, walker policy version and parse options in the build identity. Never let artifact text alter the parser globals, options or helper functions. Artifact code is not evaluated in the parser context.

Remaining pitfalls: QuickJS allocator limits do not necessarily cover FFI input buffers or all module/engine overhead. A correctly configured finite WASM linear-memory maximum adds an outer memory bound, but must leave room for parser setup, stack and transient copies. The parent implementation reports a separately verified 64 MiB maximum; this research did not reproduce that test. Test parser recursion, regexp literals, Unicode handling and teardown with the exact published variant. Keep interruption and the owner watchdog around parser setup, parse, walker, compile-only and cleanup; do not claim every C parsing/regexp path polls the callback at a proven interval. A worker/runtime bug can still require forced termination.

Suggested admission policy, an application design choice:

- Permit exactly one top-level, named, synchronous, nongenerator `FunctionDeclaration`, `update`, with the prescribed simple identifier parameters. Reject default/destructuring/rest parameters initially. Permit comments; reject additional top-level executable statements, exports and directives if the fixed wrapper owns strict mode.
- Inspect the complete AST, including nested functions: reject `ImportDeclaration`, `ImportExpression`, export nodes, `import.meta` and references to `require`/other loader interfaces. Keep the artifact dependency set empty. There is no approved module resolver or package hook in this path.
- Bound source bytes, AST nodes/depth, identifier/text lengths and validation work. Use a bounded iterative AST traversal; parser recursion remains subject to watchdog termination. Never evaluate the function to discover its name, shape, return type or dependencies.

These checks establish a declared source grammar and no declared dependencies; they do **not** prove semantic safety, termination, purity or absence of dynamically constructed code. Acorn alone does not perform scope/reference resolution. A `require` identifier check can be conservative, but banning one call spelling is not a complete alias/computed-access analysis. The runtime must independently expose no loader or host module API, regardless of parser decisions.

Regex validation is inadequate for JavaScript policy: comments, strings, templates, regex literals, Unicode-escaped identifiers and nested syntax defeat reliable keyword counting, while legitimate strings can trigger false rejection. AST checks inspect syntactic node kinds. Neither AST screening nor regex is the execution sandbox; QuickJS authority restrictions, limits and host-side output validation remain required. Do not claim that a textual ban on `eval` or `Function` closes every route to dynamic code.

## Compiler interface and output

1. Receive only validated manifest/source bytes and host-selected policy/tool versions in a disposable compiler Worker. No document text, credentials, host paths or unrelated assets need enter this request.
2. Enforce input limits before parsing. Load the pinned trusted Acorn UMD and policy walker inside bounded QuickJS; parse artifact text as a string and run the shape/dependency policy there. Return only bounded diagnostics; dispose parser state before compilation.
3. Compile the **same accepted script** with explicit QuickJS global/strict/compile-only flags and no registered module loader. Dispose the result and runtime in success/error paths. No update call, generated test, initial-state creation or source execution occurs during admission.
4. Emit a source envelope: exact UTF-8 source and its hash; manifest/input/state/event schema versions; entry symbol; compiler, Acorn, QuickJS/WASM and SDK identities; empty dependency lock; resource policy; and structured admission result. Keep measured durations/timestamps outside the deterministic content identity.
5. Hash a specified canonical serialization with domain/version separation. Preserve exact source bytes, or version an explicit normalization rule; do not silently trim/reformat source. Include effective policy and tool/WASM identities so policy changes invalidate acceptance.

This is a **compiled-source admission envelope**, not an executable browser bundle, native machine code or serialized QuickJS bytecode. Compilation success means the grammar/policy and interpreter parser accepted the source. Runtime still recompiles/interprets source only inside the separately approved guest environment. The QuickJS manual warns that its bytecode is version-specific and receives no security check before execution, supporting source-based artifacts rather than accepting externally supplied bytecode. [Upstream bytecode warning](https://bellard.org/quickjs/quickjs.html#Script-evaluation).

## Diagnostics and verification limits

Return bounded public error codes and numeric positions, a fixed virtual filename and a small sanitized message. Do not return host stack traces, filesystem paths, environment values, input snippets or private source/asset text. Store source only through the separately authorized artifact record; a build log must not become an accidental copy of a paper or secret. Parsing errors can include source-derived names, so generic messages plus locations are safer than forwarding exception strings verbatim.

Required later checks include malformed/deep/oversized scripts, Unicode/comment/template import disguises, nested dynamic imports, prohibited loader references, multiple/mis-shaped entry points, compilation failure under memory/stack pressure, owner watchdog cancellation, disposal on every branch and repeat-envelope byte identity. Demonstrate that a body containing an intentional throw/loop is **not run** during compile-only admission in the approved isolated test harness. Keep generated tests and runtime scientific checks outside this compiler stage. No such execution tests were run as part of this research.
