# Saved-source coverage and faithful fallback

PP-110 reports which parts of the **saved SourceDocument** have recorded analysis, exact links to supplied representations, or declared requirements. It never infers full-paper completeness from a prepared excerpt, an accepted quotation or a working widget. Analysis, representation linkage and scientific validity remain separate.

## Coverage model

Sections reuse the reader's exact bounded source partition, with block IDs and saved-string start/end offsets. Unique whitespace-normalized quotations map back to original offsets; ambiguous repeated quotations remain visible with zero claimed anchored characters. Neighboring planner context is excluded from selected analysis coverage.

Each section records analysis as not analyzed, partial or analyzed, independently of its representation state: represented, partially represented, missing data, missing capability, not applicable, not analyzed, or analyzed without a linked representation. Completed legacy planner records with no supported proposal count as analyzed without a representation. Pending/failed planning and absent declarations do not manufacture an analysis or a missing-capability diagnosis. Not applicable requires an explicit user-origin decision, not automatic inference from source keywords.

The model reads existing validated enrichment history and linked widgets/plans, exact checked data, named external requirements and registry diagnostics. An absent measurement table, weights or capability version remains named with a next action. Reported-only dataset cards retain their source result and explicit availability limits. No source-keyword heuristic chooses a superficially similar engine.

Reports bind the source fingerprint, exact section partition and range/count identities. Validation checks every range against its section, complementary unexplained spans, summary totals and checksum. Stale declarations, foreign ranges and self-hashed cross-section substitutions are rejected. Imported coverage files are historical declarations; they do not replace the live map, mark analysis complete or authorize execution.

## Reader actions

The compact map is available in the reading workbench and scientific study/representation previews. Source actions return to the exact block. Review opens the selected section's existing Meta controls for explicit inspection; it does not create an inference request. Linked figures and local-data import remain direct actions.

A missing or unsupported representation can open a conservative source guide, argument or protocol scaffold. The fallback quotes an original range, names the unmet requirement and suggests a reading/development next step. It executes no algorithm and invents no measurements, proof steps or missing protocol details. Generic section guides prefer a substantive non-heading passage within the allowed scope; explicit narrow targets are not widened. Saved logical pages are never relabeled as physical pages of an unretained article. The requested representation remains recoverable in the preview.

A local table can be inspected as a separate source-linked study. It is not silently substituted for a publication's missing raw data. Current source text, imported originals and incompatible history remain available independently of coverage.

## Developer extension requests

A local review produces a strict request of at most 64 KiB. Default content is source/section/concept identities and hashes, unmet requirement/version/digest identities, gap kinds and an explicit rights/disclosure note. Source titles, headings, claims, excerpts, raw file bytes, private asset manifests, provider jobs and credentials are not copied automatically. Requirement labels and rights notes are visible before download and can themselves describe private work.

Original excerpts require an unchecked-by-default opt-in and explicit exact range selection, at most eight ranges and 4,000 saved-string characters in total. The export preserves each selected range and its text hash. It is an inert download, not a job submission, code installation, grant of redistribution rights or scientific verification. Imported requests remain reported history and cannot activate an adapter.

## Evidence and limits

The development cases use the existing B1 Hodgkin–Huxley attribution card and C1 priority-search-tree selection. B1's logical page 1 is not original printed page 521; C1's complete local blocks are not the complete eighteen-page paper. See [development admission and boundary cases](coverage-development-cases.md).

Native browser checks cover an automatic B1 missing-data report, an authored request for the unavailable `isabelle-proof-replay@1.0.0` capability on C1, exact source return, provider-free fallback, default metadata-only versus explicitly selected excerpt export, recovery and responsive reading. These are engineering observations; no held-out tuning, paid inference, human-reader results, domain expert approval or release work is claimed.
