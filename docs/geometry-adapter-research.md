# PP-103: reviewed molecular/structural geometry adapter

Primary-source research checked 28 October 2026 for [PP-103 / issue 58](scientific-backlog.json). No application code, package, structure asset or image was added. Only this note is written; original coordinate downloads remain in `/tmp`. No inference, docking, dynamics simulation or scientific validation was performed. No held-out corpus example was used.

**Recommendation:** begin with a reviewed, bounded legacy-PDB coordinate reader and a trusted SVG orthographic 3D point viewer with rotation, clipping, identity-linked selection and a numerical/2D fallback. Keep mmCIF and a full molecular viewer behind a later adapter admission. This gives a genuine small structure now without promising general molecular parsing or introducing a broad rendering dependency prematurely.

## What must survive parsing

The official [wwPDB PDB 3.3 coordinate specification](https://www.wwpdb.org/documentation/file-format-content/format33/sect9.html) defines fixed-column `ATOM`/`HETATM`, model records, atom serial/name, alternate location, residue name/sequence/insertion code, chain, coordinates, occupancy, element and temperature factor. Coordinates are orthogonal Cartesian ångströms. Parse those columns, not whitespace-separated tokens; a blank chain or insertion code remains meaningful. Missing `MODEL` records mean a single coordinate set, not a source-supplied model serial. Preserve raw source references instead of fabricating deposited identifiers.

Use a stable entity identity derived from source-byte hash plus model/chain/residue-number/insertion-code/residue-name/atom-name/alternate-location and source record identity. Keep raw serial/name fields separately from normalized labels; serial alone is insufficient across models. Distinct atoms at coincident coordinates are not duplicates. `CA` atom name is not proof of calcium: use the declared element field. Preserve `TER` boundaries. Reject duplicate ambiguous identities rather than silently merging them. For mmCIF extension, preserve both author and label namespaces; the [wwPDB atomic-description tutorial](https://mmcif.wwpdb.org/docs/tutorials/content/atomic-description.html) explicitly distinguishes them, model IDs, insertion codes and alternate sites.

Expose an explicit model/conformer choice. Never average alternate positions or silently take the largest occupancy; occupancy is not a statistical sample weight for inventing an average molecule. A bounded initial implementation can reject unsupported alternate-location or multiple-model combinations while retaining the original file. If supported, labels/selections and distance requests must name the exact variants and model. Do not mix models into one apparent molecule or compare coordinates from differently aligned models without an explicit correspondence/alignment operation.

## PDB first, mmCIF deliberately deferred

[PDBx/mmCIF is the current archive format](https://www.ebi.ac.uk/training/online/courses/navigating-alphafold-database/understanding-the-structure-prediction-page/downloading-files/). Its [official user guide](https://mmcif.wwpdb.org/docs/user-guide/guide.html) defines data blocks, keyed values, `loop_` tables, quoted values, semicolon multiline strings, comments and missing/not-applicable markers `?`/`.`. It is not safely implemented by splitting lines or whitespace. Preserve unknown versus not-applicable semantics; do not replace either with zero. The [atom-site dictionary](https://mmcif.wwpdb.org/dictionaries/mmcif_pdbx_v50.dic/Categories/atom_site.html) supplies field identities, and [Cartn_x](https://mmcif.wwpdb.org/dictionaries/mmcif_pdbx_v50.dic/Items/_atom_site.Cartn_x.html) explicitly specifies ångströms.

An initial `.pdb` reader should recognize/reject CIF input as unsupported rather than return an empty success, reject hybrid/overflow serial encodings it does not implement, and disclose ignored metadata categories. No automatic format conversion service or remote parser is needed. A later mmCIF adapter needs a reviewed tokenizer, bounded loops/rows/strings, retained namespaces and missing-value semantics, and fixtures covering quoted atom names and multiline metadata. BinaryCIF, PDBML, PQR, SDF, compressed archives and integrative/coarse-grained structures remain unsupported until separately reviewed. A file extension never establishes a valid format.

## Connectivity, missing atoms and assemblies

The [wwPDB CONECT specification](https://www.wwpdb.org/documentation/file-format-content/format33/sect10.html) defines explicit serial-based connections and explains that standard residue connectivity is generally not listed there. Thus an absent CONECT row is not proof of no bond, and close coordinates are not proof of a bond. The initial view can safely render atoms with **no inferred bonds**. If source-declared edges are included, retain their record/category and endpoints, deduplicate reciprocal references and label type/order unknown where the source does not specify it. Do not turn every CONECT edge into a demonstrated covalent single bond or invent hydrogen bonds, ligands or secondary structure by proximity.

Do not fill missing residues/side chains/hydrogens or interpolate a polymer trace through absent coordinates. Sequence annotations and coordinate rows describe different things; the [PDB primary-structure guide](https://www.wwpdb.org/documentation/file-format-content/format33/sect3.html) distinguishes deposited sequence and cross-references. Retain gaps and unsupported annotations as limitations.

An asymmetric-unit coordinate set is not automatically the complete biological assembly. The [mmCIF assembly guide](https://mmcif.wwpdb.org/docs/user-guide/guide.html#assembly) specifies separate assembly/generator/operator descriptions. Initial support should display the deposited coordinate set only, explicitly omitting symmetry/assembly expansion. Never infer an oligomer or apply transformations silently; a future assembly choice needs its operator provenance, transformed-instance identity and expanded-atom budget.

## Coordinate units and measurements

An ångström is exactly `10^-10 m`, or `0.1 nm`; [IUPAC Gold Book N00350](https://goldbook.iupac.org/terms/view/N00350) confirms the definition. The repository's current scientific unit catalog has nm/m but not Å. Either add a reviewed Å unit with a catalog/version change, or retain the raw Å coordinates and explicitly convert the normalized physical representation to nm. Do not relabel the same numbers as nm. Preserve original units and the transformation so exports and measurements remain interpretable.

Measure `sqrt(dx²+dy²+dz²)` in the original common 3D frame, independent of camera rotation, zoom, clipping and projected screen distances. Bind every measurement to file hash, exact atom IDs, model/conformer and coordinate transform. Residue selection is a set of known atoms; a residue centroid or closest-pair distance needs an explicitly named aggregation rule, not an invented representative atom. Reject absent/ambiguous selections and incompatible frames. A computed coordinate distance is not a bond assignment or a coordinate-uncertainty interval. Source B-factors must not be converted into distance error bars.

## Experimental versus predicted structure fields

Keep an explicit provenance classification: experimental coordinate model, predicted model or unknown. Experimental coordinates are refined structural models; they are not literal observations of every atomic position. The [wwPDB B-factor dictionary](https://mmcif.wwpdb.org/dictionaries/mmcif_pdbx_v50.dic/Items/_atom_site.B_iso_or_equiv.html) defines an atomic displacement parameter; it does not define per-atom prediction confidence or a coordinate confidence interval. Missing displacement/occupancy values stay missing.

AlphaFold DB's [official FAQ](https://alphafold.ebi.ac.uk/faq) identifies pLDDT as a local predicted-confidence score, not experimental B-factor; its PDB downloads use the B-factor field for that different quantity. Do not infer this interpretation from a numeric range or `.pdb` filename. ModelCIF can instead carry residue-level QA in [`ma_qa_metric_local`](https://mmcif.wwpdb.org/dictionaries/mmcif_ma.dic/Categories/ma_qa_metric_local.html), joined to a declared [metric type](https://mmcif.wwpdb.org/dictionaries/mmcif_ma.dic/Items/_ma_qa_metric.type.html). Read the actual metric declaration/scale; do not assume every score is pLDDT or every mmCIF file stores it as B_iso. PAE concerns relative placement and is a different metric; pLDDT alone does not certify interfaces or inter-domain geometry. The [2024 database paper](https://academic.oup.com/nar/advance-article-pdf/doi/10.1093/nar/gkad1011/52777135/gkad1011.pdf) describes the PDB versus ModelCIF storage distinction.

Development case **B4 AlphaFold** can explain this coordinate/confidence pipeline with its existing source mapping, without running AlphaFold or presenting an unrelated crystal model as an AlphaFold output. A genuine AFDB file would require its own accession, model version, original bytes/checksum, attribution and metric mapping before admission. AFDB predictions are [CC BY 4.0 with attribution requirements](https://alphafold.ebi.ac.uk/); this does not transfer rights to arbitrary linked articles/assets. The small experimental fixture below is independently labeled and does not reproduce the B4 prediction experiment.

## Rendering dependency decision

The existing repository has no molecular renderer, and its generic geometry asset has only vertices/faces. It cannot preserve molecular identifiers by itself. Add a versioned molecular asset contract and an application-owned adapter, keeping parsing/identity/measurements independent of the renderer.

## Minimal implementation gates

Proposed ceilings: uncompressed input ≤256 KiB, ≤10,000 lines, ≤4,096 characters/line, ≤512 total atom sites, ≤256 residues, ≤8 chains, ≤4 models and ≤1,024 explicit connections. Count all imported model/altloc sites before view filtering; do not truncate and claim success. Bounds are proposed product choices, not measured performance. Decode bounded text, reject malformed/empty coordinate data and parse in a disposable trusted worker if needed for responsiveness. Preserve unsupported originals with export and a plain explanation. No arbitrary URL loads, scripts or imported renderer configuration.

Use at most a bounded selection/label set in the drawing and retain every accepted row in a keyboard-accessible table. Rotation/clipping alter presentation only; source coordinates, IDs and distances remain unchanged. Provide XY/XZ/YZ projections and exact coordinate/distance inspection when a 3D renderer/context is unavailable. Stop/error/source controls belong to the host. A failed graphical view must not erase the accepted structure or start replacement inference.

Version/cache file bytes, parser policy, units, selected model/conformer, any declared assembly transform and measurement definitions separately from camera settings. Editing an identifier, source coordinate or active model invalidates affected measurements and semantic selections; rotating the camera does not. Portable exports need explicit attachment/data choices and the exact source/rights/checksum provenance. Report engineering parser/render/distance checks separately from scientific fidelity. Implementation remains gated until the preceding issues are complete; this document supplies evidence and a bounded proposal only.
